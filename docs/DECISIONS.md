# Decisions

Chronological log of decisions made without asking. Newest at the bottom.

## 2026-09-27

1. **Vite over Bun HTML imports.** The bun-init CLAUDE.md said "don't use vite"; the brief says Vite + React + TypeScript. The brief wins. Vite gives `--host` for the phone and proxies `/api` to the Bun server, so one URL works on the iPhone.
2. **Stray nested `remnant/.git` removed.** It was an empty accidental `git init` inside the repo. Also removed the `index.ts` hello-world.
3. **The fixture is a real WhatsApp export.** `fixtures/sarah/sarah.whatsapp.txt` is parsed by the real WhatsApp adapter at load time, so the demo path exercises an import adapter instead of bypassing it.
4. **Persona's "first message" is its first reply.** The brief asks both for a corpus-derived first message and for `noInitiate`. Resolution: the thread opens on the REAL history ending in Sarah's last real text, 8 months ago. The persona says nothing until the user texts. Its first reply then opens with her corpus-derived greeting (the stylometry `greetings` field, "hi hi"). A reply is not an initiation.
5. **GBrain lock and `GBRAIN_HOME`.** PGLite is single-writer and `gbrain serve` refuses to start while another live serve holds the lock. A `gbrain serve` MCP child of the Claude Code session was still holding `~/.gbrain` (the `~/.claude.json` entry under project `/Users/kartik` was not actually removed), and the permission classifier blocked killing it or editing that file. gbrain honors `GBRAIN_HOME` as the parent of `.gbrain/`, so the server sets `GBRAIN_HOME` from `REMNANT_GBRAIN_HOME` (default: the user's home, i.e. `~/.gbrain` as the brief asks; during dev: `~/.remnant-dev`, see decision 10). If the child exits with a live-serve lock error the server logs the exact fix.
6. **`gbrain import` runs from the server, not a Claude MCP.** `bun run brain:import` runs `gbrain import brain/ --no-embed` before the server spawns `gbrain serve`, because both need the PGLite lock and only one process may hold it.
7. **Consent store is a JSON file** under `.remnant/consent.json`, not a database. It is one record for the demo and must survive restarts; a file is the honest minimum.
8. **Model provider order:** River adapter (if `training/runs/latest.json` has a checkpoint) → Anthropic (if `ANTHROPIC_API_KEY`) → Fixture (deterministic). The active provider is shown in the UI footer so the fallback is never silent.
9. **`synthesize` verb not used at runtime.** It runs an LLM inside gbrain; the persona prompt already reasons over retrieved facts. Using it would double the model calls and hide which memories were used.
10. **The dev brain lives outside the repo.** A PGLite brain initialised inside this git worktree (`.remnant/.gbrain`) accepted `gbrain import` but every `remember` failed with `storage_error: The write did not commit` (gbrain's init warned the content dir was "inside another Git worktree" and refused to claim it). Re-initialising at `~/.remnant-dev` fixed it: 78/78 facts inserted. `REMNANT_GBRAIN_HOME=~/.remnant-dev` for dev; unset for `~/.gbrain`.
11. **Memories are GBrain facts, not just pages.** `recall`'s page-search arm is keyword-only without an embedding provider and missed obvious queries ("hair appointment" returned nothing). The facts arm (written via `remember`, filtered by entity) is reliable, so the import script writes every Compiled Truth sentence and Timeline event as a fact with the page as provenance, and `recall` ranks facts by overlap client-side. Every hit the persona uses therefore has a `brain/...md` provenance the UI can show.
12. **River run done, RiverProvider is now the default in the demo.** `Qwen/Qwen3.8-27B-FP8` was enabled for the key. Run `training/runs/20260927T212125Z`: LoRA rank 16, 95 chat examples, 36 steps at lr 1e-4, loss 4.19 -> 0.75, inference checkpoint saved (path in `training/runs/latest.json`). Inference goes through `training/serve.py` (Python, holds one River session) because river-client is gRPC/Python only; `RiverProvider.detect()` needs both the manifest and a healthy sidecar, otherwise the footer says which fallback is active.
13. **Two neverAlive gaps found in live River output and closed in code.** "im still in the chair" (an adverb between "im" and "in") and a bare "ya" to "do you miss me" (no verb at all) both passed the classifier. The first got an optional `still/already` in the presence pattern; the second got a context-aware check (`classifyInContext`) that treats a bare affirmative to a present-feeling question as a violation and substitutes a timeless line. Both are tested. The prompt already forbids these; the classifier is the backstop, and the live run showed why it must exist.
14. **Scripted demo mode exists so the film is deterministic; live mode is the product.** `?demo=sarah` loads the same fixture thread and footer but replaces only the model call with `fixtures/sarah/demo-script.json` (three hand-typed sends -> fixed bursts with fixed waits, then the call button pulses; the call screen runs its waveform and timer with no audio, which is added in the edit). Steps fire in order on each send so a typo on camera does not derail the take. The script is validated and run through the same neverAlive, crisis, and StyleEnforcer-shape checks as live output in `packages/core/src/demo.test.ts`. Nothing in the live pipeline reads the script.
15. **Demo call audio is pre-rendered and tap-advanced.** Six ElevenLabs v3 clips (`fixtures/sarah/call-script.json` -> `fixtures/sarah/call/NN.mp3`, generated by `apps/web/scripts/sarah-voice.ts` with the voice in `ELEVENLABS_VOICE_ID`) play in order on a tap anywhere on the demo call screen, with no visible control; after the sixth, taps do nothing. The waveform is driven by a Web Audio AnalyserNode on the playing element, so what the camera sees is the real amplitude. Live mode still fetches TTS per reply. ElevenLabs rejects a line that is only an audio tag, and returns empty audio for a tag plus punctuation, so line 2 is `[breath] mm.` rather than a bare `[breath]`. The spoken words of every line pass neverAlive in the demo test.
16. **Consecutive-burst gap is 6px, and the call screen names the voice, not its provenance.** 4px read too tight at 78% bubble width on a 390px screen. Whether the voice is cloned or a library voice stays in the persona/voice record (`/api/state` `voice.cloned`, `voice.label`) and the settings side, not on the call UI, whose status line now shows only the voice name.
17. **Secrets audit found nothing; `.env.example` documents every variable.** Every commit on every branch was scanned for `sk_` and `rv_` key values, `xi-api-key` values and any `.env` content. `.env` was never tracked and no value ever appeared, so no history rewrite was needed. `.env.example` lists all eleven variables the code reads, each with a one-line comment, and the app names whichever fallback it takes when one is missing.
18. **One command each: `bun run demo` and `bun run sarah`.** `scripts/demo.ts` runs the brain init/import/seed, the River sidecar when `RIVER_API_KEY`, a `.venv` and `training/runs/latest.json` exist (otherwise it prints the fallback), the Bun API and Vite, then one readiness check that prints the URLs and the health JSON; it waits for the sidecar before the API because the API picks its provider once at boot. `scripts/sarah.ts` rebuilds the persona from `fixtures/`: adapter, fingerprint, brain audit, GBrain import. `PORT` and `WEB_PORT` are honoured by the API, Vite and the demo script so a second stack can run beside the live one. `gbrain init` exits 1 when the parent directory is missing or any path component is a symlink (`/tmp` on macOS is one), so the helper creates the directory and hands gbrain the real path. Both commands were verified from a fresh clone in `/tmp`.
19. **`fingerprint.json` and `auditBrain` are drift tests, not features.** `bun run sarah` writes the measured style to `fixtures/sarah/fingerprint.json` and a test fails if the file no longer equals `computeFingerprint(corpus)`. `auditBrain` checks that every page in `brain/` has a Compiled Truth section that yields facts, that every page under `memories/sarah/` belongs to `people/sarah`, that the person page quotes the corpus's real last message and that the style page names the measured greeting. The hand-written pages stay hand-written; the audit is what keeps them honest.
20. **`GET /api/health` is the single source for what the UI claims.** It returns the provider id (renamed from `river` to `river-finetuned`), its label, whether it is an owned model, its fallback note, the memory backend (`MemoryStore.backend`: `gbrain-stdio`, `gbrain-http` or `memory`, alongside the unchanged `kind`), the memory note, the active fact count for `people/sarah` and `GUARDRAILS_VERSION` (1.2.0, with a changelog in `guardrails/index.ts`). The footer now reads it instead of `/api/state`, and prints exactly the text it printed before; nothing visible was added.
21. **Hosted brain via `GBRAIN_MCP_URL`, implemented but not exercised live.** With the variable set, `GBrainMemoryStore` uses the MCP SDK's `StreamableHTTPClientTransport` with a bearer token from `GBRAIN_MCP_TOKEN` instead of spawning `gbrain serve`, and `bun run demo` skips the local import. It typechecks and the stdio path is unchanged, but no `gbrain serve --http` was stood up today, so the README lists it as a limitation rather than a claim.
22. **CI pins the timezone and dry-runs the export.** `.github/workflows/ci.yml` runs `bun install --frozen-lockfile`, `bun run typecheck`, `bun test` and `python training/export_sft.py --dry-run` with `TZ=America/Los_Angeles`, because the fixture's timestamps are local-time. `--dry-run` builds the chat examples with the standard library only, prints the stats and writes nothing, and exits non-zero if fewer than 70 examples come out.
23. **The server is `bootstrap.ts` plus `app.ts`, with route tests.** `bootstrap` takes knobs (`memory`, `provider`, `voice`, `dataDir`) so `app.test.ts` can boot the real server on a random port with the in-memory facts and the fixture provider, no keys, no gbrain child, no network, and check health, consent gating, a chat turn with provenance, the crisis bypass, the demo scripts and the disabled voice route. Production runs with the defaults and the environment.
24. **The in-memory fallback holds the same facts as the brain.** `bootstrap` used to parse Compiled Truth paragraphs on its own; it now seeds `InMemoryStore` through `parseBrainFacts`, the function `bun run sarah` uses for GBrain, so the fallback carries the same 78 sentence-level facts with kinds and provenance.
25. **Test temp dirs come from `os.tmpdir()`.** CI failed on two tests that created files under a hardcoded macOS scratchpad path. They now use `mkdtempSync(join(tmpdir(), ...))`, which is also what the new route tests and the brain audit test do.
26. **The River run is committed as evidence.** `training/runs/latest.json` and `training/runs/20260927T212125Z/{manifest.json,log.jsonl}` are un-ignored so a reviewer can read the step losses, the holdout samples and the checkpoint path without a key. The checkpoint path is not a secret; it is loadable only with the key that trained it.
27. **One-off filming scripts are gone.** `apps/web/scripts/screens-15pro.ts` and the seven `docs/screens/15pro-*.png` before/after shots existed for a single spacing fix on the iPhone 15 Pro. The fix is in the CSS and its commit; the scaffolding is not load-bearing and was removed so the tree holds only code that runs.
28. **Unused ElevenLabs methods removed.** `ElevenLabsVoice.listVoices` and `deleteVoice` had no caller and no test; the second self-review pass in `docs/REVIEW.md` named them the most visible leftover and they are gone. What remains in `services/voice/` is exactly what the server calls: clone, speak, and the JSON voice record.
